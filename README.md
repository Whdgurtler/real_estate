# Groundwork — Property Acquisition & Underwriting

A single-operator workspace for residential property leads, local market signals, and rental underwriting. The initial release is designed for national data models with Arkansas, Alabama, Ohio, Missouri, and Texas prioritized in the workflow.

## What works

- Add a conventional, tax-sale, code-enforcement, foreclosure, or pre-foreclosure lead manually; retain its source URL and evidence for supplied metrics.
- Edit existing opportunities without losing unsubmitted fields; new values append source-attributed metric evidence to the ledger.
- Import property records from UTF-8 CSV. Required columns: `address`, `city`, and two-letter `state`. Other accepted columns use the field names in `backend/app/schemas.py`.
- Search and filter the pipeline by state and maximum asking price, view geocoded properties on an OpenStreetMap-backed map, and inspect a source-aware property detail view.
- Calculate tax from a supplied annual bill or from assessed value × supplied tax rate. There is no universal insurance formula: enter a quote or a clearly attributed user estimate.
- Compare market-rent inputs with Section 8 screening benchmarks from HUD Fair Market Rent and PHA payment-standard inputs. A PHA must be marked confirmed before the Section 8 underwriting scenario is shown.
- Keep program participation, waitlist status, and open voucher counts separate. A missing count remains unknown; it is never derived from a waitlist status.
- Retrieve county population estimates from the Census Bureau ACS 5-year API using a five-digit county FIPS code. The displayed annual growth rate is annualized from the configured vintage and the vintage five years earlier.
- Refresh saved Census population metrics daily for properties with county FIPS codes. With a HUD USER API key, refresh ZIP- and bedroom-specific Fair Market Rent benchmarks daily as well.
- Configure daily Socrata, ArcGIS FeatureServer, or public JSON API feeds for county assessor, tax-sale, code-enforcement, foreclosure, pre-foreclosure, and other jurisdiction datasets. Field mappings normalize records into the property pipeline; repeated records are linked and updated without duplicating evidence.
- Browse all 599 Census county-equivalents in Arkansas, Alabama, Ohio, Missouri, and Texas (including St. Louis city and all 254 Texas counties), find assessor/tax-sale/code-enforcement/foreclosure/pre-foreclosure source-discovery links by county, and see whether a feed is configured, paused, or still needs a verified endpoint.
- Inspect sync history, per-source errors and skipped records, and the next scheduled run; queue a manual run from **Data sources**.
- Score available yield, population-growth, and crime-safety inputs with configurable weights. The response exposes formulas and data coverage; missing inputs are excluded and not treated as zero.
- Keep evidence sources separate by property lead, tax, insurance, market rent, HUD, PHA, and neighborhood metrics; display the recorded source, confidence, and capture date in the evidence ledger.
- Find nearby geocoded opportunities. PostgreSQL uses PostGIS and a GiST spatial index; local SQLite development uses a great-circle distance calculation.

## Daily data automation and source setup

The API starts a daily scheduler at **02:00 America/Chicago** by default. Configure the schedule before starting the API:

```powershell
$env:DAILY_SYNC_ENABLED = "true"
$env:DAILY_SYNC_TIME = "02:00"
$env:DAILY_SYNC_TIMEZONE = "America/Chicago"
$env:CENSUS_ACS_YEAR = "2024"
```

`DAILY_SYNC_TIME` uses 24-hour `HH:MM` local time and `DAILY_SYNC_TIMEZONE` must be an IANA time-zone name. Set `DAILY_SYNC_ENABLED` to `false` to disable the daily timer; the run-now executor remains available. The database enforces a single active run and a unique scheduled run per local calendar date, so multiple API workers do not duplicate the daily execution. For production, use PostgreSQL rather than SQLite when running multiple workers.

Set `HUD_API_KEY` to enable the official HUD USER FMR API refresh. `HUD_FMR_YEAR` optionally pins a Fair Market Rent data year; otherwise the current calendar year is requested. HUD enrichment requires both a five-digit ZIP code and a known bedroom count. FMR is a screening benchmark, not the administering PHA's payment standard or a promise of rent approval.

The **Data sources** view can register public Socrata, ArcGIS FeatureServer, or JSON API feeds. Choose **Property leads** to map upstream address, city, and state fields; add a stable record ID field when available. Choose **Area enrichment** to match existing properties by county FIPS, ZIP plus state, or county plus state and refresh only area-level population, crime, rent, or PHA metrics. Optional server-side API credentials are specified by environment-variable *name* in the feed configuration (for example, `TAXLIENSIMPLE_API_KEY`) and are never stored in the database; select a query-parameter name only for APIs that require API keys in query strings. For Socrata, `SOCRATA_APP_TOKEN` is optional. Use provider-approved APIs and review source terms and licensing before enabling feeds. JSON API pagination expects `limit`/`offset` parameters when the provider supports them.

Examples of the supported feed patterns:

- **Socrata:** use the jurisdiction's dataset domain and 4-by-4 dataset ID, then map its address/city/state, parcel ID, assessed value, tax bill, code case, or crime-rate fields.
- **ArcGIS:** use the public FeatureServer layer URL (not the dashboard page); map the layer's attribute fields.
- **Tax-sale JSON API:** TaxLienSimple documents `GET https://taxliensimple.com/api/v1/parcels`, `Authorization: Bearer …`, and `state`, `county`, and `family` filters. Set the token in `TAXLIENSIMPLE_API_KEY`, use that environment-variable name for the feed, and map only fields actually returned. Its published parcel schema does not guarantee a city field; records without the required address/city/state are explicitly skipped rather than assigned an invented location.
- **Commercial parcel/insurance providers:** Regrid and insurer quote platforms require a separate account and appropriate use/redistribution rights. A JSON API feed can be configured only after the provider grants access and its endpoint/response schema are known.

Feed retrieval is capped at 5,000 records per run and 10 MB per response page. Stable source IDs are used to upsert records; records without IDs use normalized address/city/state as a fallback. Invalid or incomplete rows are counted as skipped and shown in sync results. A configured feed is not evidence that the provider covers a whole state or refreshes daily; verify coverage, terms, and publication cadence with the source. For ArcGIS and Socrata feeds, the executor requests only fields named in the field mapping and optional record-ID field; it does not request every attribute from the service.

The priority-county registry is generated from the U.S. Census Bureau national county-equivalent FIPS reference and covers 599 counties/county-equivalents across Alabama, Arkansas, Missouri, Ohio, and Texas. The source directory links to the Alabama Department of Revenue county assessment pages, Association of Arkansas Counties county profiles, County Auditors' Association of Ohio directory, Missouri State Tax Commission/Missouri Association of Counties directories, and Texas Comptroller/Texas Association of Counties/Texas Municipal League resources. Foreclosure and pre-foreclosure discovery links lead to state judiciary, county-office, or association resources plus county-specific searches; they are not claims that each county exposes an API, complete sale calendar, or pre-foreclosure notice feed. Foreclosure and notice publication processes vary by state and county, and some listings require an authorized commercial provider. The daily executor only retrieves feeds explicitly configured and verified by the operator; discovery links are not scraped as feeds. Code enforcement is often municipal, and tax-sale feeds are administered locally or require a provider account. The county coverage view intentionally labels those local endpoints as unconfigured until an actual feed has been verified and registered.

FBI Crime Data Explorer data is reported by law-enforcement agency and requires an API key plus an explicit, verified agency/geography mapping; it is not a block-level crime feed. Import official FBI summaries or configure an appropriate local government feed and map its documented rate to `violent_crime_rate_per_100k`. HUD/PHA coverage, payment standards, waitlist status, and open-voucher counts are distinct facts; the system does not infer voucher counts from PHA participation or waitlist status.

There is no comprehensive public nationwide property-level insurance quote API. Insurance premiums remain quote- or CSV-based unless a licensed carrier/broker provider is separately selected and authorized. The system does not fill missing insurance costs with an unsupported estimate. Nationwide parcel assessment, code-enforcement, and tax-sale coverage is also not a universal feed: configure the relevant jurisdiction or a licensed data provider for each market.

## Run locally on Windows

Requires Python 3.11+ and Node.js 18+.

From the repository root, install the Python package and development test dependency:

```powershell
python -m pip install -e ".[dev]"
```

Start the API (SQLite is used by default):

```powershell
python -m alembic upgrade head
python -m uvicorn app.main:app --app-dir backend --reload --port 8001
```

In another PowerShell window, install and start the React client:

```powershell
Set-Location frontend
npm install
npm run dev
```

Open the Vite URL (normally `http://localhost:5173`). FastAPI API documentation is at `http://127.0.0.1:8001/docs`.

For Census enrichment, provide a property county FIPS (two state digits followed by three county digits) and use **Refresh county population from Census ACS**. Set `CENSUS_ACS_YEAR` to another available ACS 5-year vintage if needed; the default is 2024. Census requests require outbound internet access.

## PostgreSQL / PostGIS

Install PostGIS on the PostgreSQL server, configure `DATABASE_URL`, and run migrations before starting the API:

```powershell
$env:DATABASE_URL = "postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE"
python -m alembic upgrade head
python -m uvicorn app.main:app --app-dir backend --reload --port 8001
```

The API verifies/installs the PostGIS extension and maintains the point geometry from latitude/longitude on startup. The database role therefore needs permission to create the extension if it is not already installed. Set `ALLOWED_ORIGINS` to a comma-separated list before deployment.
